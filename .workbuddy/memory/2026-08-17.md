## 诊断：联网搜索后"相关度=1 仍标疑似幻觉"
用户问为何。结论：**"相关度"与"疑似幻觉"是两条独立关卡**，不是同一指标。
- 检索/评估相关度（RRF score、evaluator_score，决定"来源够不够好用来生成"）是 source 层面；
- 幻觉检测（`SemanticVerifierDetector.detect`，`app/adapters/detector/semantic_verifier.py`，默认 provider=semantic）是 answer 层面：生成后把答案每句与所引来源块做嵌入余弦（阈值 0.6），`verified = 无句被怀疑`，任一句 <0.6 或整句无 `[N]` 引用 → suspected。
- web 块文本为 `【网页】标题(url)\n内容(截800字)`（`web_retriever.py` L65），检测器对整个串嵌入：`【网页】`+URL 前缀带偏向量、800 字截断可能切掉答案对应原句 → 余弦常 <0.6 → 标疑似。本地干净文档块易过 0.6，web 难。
- 额外潜在 bug：`_backtrack_parent_chunks`（orchestration.py L195）对 web 块（parent_id=None→target="web_0" 不在 Chroma 父块映射）→ `continue` 跳过；仅当 top 中**无本地父块**时才 `return chunks` 把 web 块放进上下文。即"本地+网页混合"时网页块被丢弃，联网形同无效。
- 修复方向（待用户确认是否改）：检测前剥离 web 块 `【网页】` 前缀/用纯净 content 嵌入；web 来源单独降阈值或标外部权威直接通过；修 backtrack 让 web 块在混合场景也进上下文。

## Reranker 与上下文压缩审计（用户列 8 问 + 前 3 问复查）
复用本会话已落地的"检索内并发 + query 缓存"结论，并查 reranker/chunker/cleaner/orchestration 实际代码：
- reranker：`BGEReranker`(bge_reranker.py) 用 `sentence_transformers.CrossEncoder`，默认 `BAAI/bge-reranker-v2-m3`，`batch_size=32`；`RerankerConfig.rerank_top_k=5`(config L114)；`IdentityReranker` 直通回退。
- 去重链路：① retrieve 末步"家族去重"（同 `parent_id` 子块最多 2 条，hybrid_rrf L231-239）；② `_fuse_variants` 按 `chunk_id` 融合去重；③ `_backtrack_parent_chunks` 用 `seen` 对父块去重（web 块单独去重保留）。
- 噪声：`cleaner._strip_noise`（入库期）频控去重(同短行≥3 剔除=页眉页脚) + 可配 `noise_patterns`；`ChunkConfig.noise=True` 默认开，ingestion 调用。
- 上下文压缩：仅 A1 会话历史摘要(`_summarize_history`)；检索命中块送 LLM 前**不压缩**（`_backtrack_parent_chunks` 返父块全文；context=完整文本），唯一的 `_SOURCE_TEXT_LIMIT=300` 只截 API 响应 `sources[].chunk` 片段。→ 规避"过度压缩误删数字/单位/条件"（代价：上下文可能偏长）。
- **缺口（待改进候选）**：① reranker 无专属超时/并发池，仅 request 级信号量(4) + request_timeout 预算兜底；CrossEncoder CPU+GIL，并发请求各自 predict 串行挤占；② 无领域适配/微调（通用 v2-m3）；③ `rerank_top_k` 固定 5，无动态质量阈值（召回不足仍硬塞 5 块）；④ 不同 `document_id` 的"同文档不同版本"不去重（仅同 parent_id 家族去重）；⑤ lost-in-middle 仅靠 rerank 降序(首因效应)，无"关键事实置首尾/中段加权"专门策略。
