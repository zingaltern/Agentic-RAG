## 幻觉在线检测审计（用户问答）
- 检测器体系：`HallucinationDetector` 抽象接口（interfaces.py:95，`detect(answer, context)->DetectionResult`），
  两个实现：`CitationTracingDetector`（字符 2-gram Jaccard，阈值 0.8，纯 Python）与
  `SemanticVerifierDetector`（默认，句⊕引用块嵌入余弦，阈值 0.6，需注入 embedding）。
- 配置：`DetectorConfig`（config.py:132），`provider="semantic"`（W5 升级），`similarity_threshold=0.8`、`semantic_similarity_threshold=0.6`。
- 触发点：编排层每轮 LLM 生成后调用 `self.detector.detect(answer_text, context)`（orchestration.py:372），即"在线"。
- 关键边界（重要）：检测结果**只作为返回给用户的质量判词**（api/query.py:45-46 → hallucination_check=passed/suspected，citations.confirmed=verified_rate），
  **并不回灌反思循环**；反思循环由独立的 Evaluator 的 `result.passed` 驱动（detector 仅在 `passed or web_active` 分支里计算后直接 return）。
  → 即"在线检测"是事后裁决信号，不是强制重答的闸门。
- 算法共性：按 。！？ 切句 → 正则 `\[(\d+)\]` 取引用 → 无引用整句判 suspected → 句与所引块相似度 ≥ 阈值才 confirmed；verified = 无 suspect，verified_rate=confirmed/总句。
- 局限：检测不强制重写；仅中文句末标点切句；依赖 LLM 真的写出 `[N]`（漏标整句全 suspect）；只做句↔块相似，无跨句推理校验。

## 联网搜索"没效果"排查（用户授权动手）
- 用户现象：APP 端开了联网搜索开关但无效果。
- 已排除：前端开关→后端→编排 全链路通（QueryConsole.vue 传 `web_search`、api/query.py 接收透传、orchestration 触发）；key 加载通（`config.py:_env_source_dict` 在 `load_config` 时把 `.env` 的 `RAG_*` 回写 os.environ，已点名 WebRetriever；`.env` 中 key 57 位真实值）。
- **实测**：在当前沙箱环境直接 `WebRetriever.retrieve("...")` 成功返回 2 条真实网页 → 代码 + key + 网络 全正常。
- **根因 = 运行环境网络/代理差异**：`web_retriever.py` 用裸 `urllib.request.urlopen(req, timeout=8)`，**只靠环境 `HTTPS_PROXY` 隐式继承，无代理配置项、无显式代理处理**。沙箱能通是因 Bash 环境有 `HTTPS_PROXY=127.0.0.1:51783`；用户后端进程若无此代理（大陆直连 api.tavily.com 不通）→ 8s 超时**静默返回 []** → "没效果"。
- 代码脆弱点：① WebRetriever 代理不可配置、纯依赖隐式环境；② 失败/未配置均静默（仅 logger，不向用户提示）。
- 建议修法（未实施，待用户确认）：让 `WebConfig` 支持 `proxy`（或显式读 `HTTPS_PROXY` 并传 `urllib.ProxyHandler`）+ 联网未配置/失败时向用户显式提示（sources 加 notice 或 answer 标注），避免静默失败。

## 《在线侧输入处理.md》（RAG输入侧治理蓝图）对照项目完成度审计
- 文档是"输入侧治理"完整蓝图：L0 复杂度分级调度 → L1 输入标准化 → L2 对话状态引擎 → L3 智能路由与分解 → L4 结构化提取 + 安全/韧性横切。
- 逐项核对代码后结论（约 29 个可核查子能力）：
  - **明确完成 4 项**：① L1 基础归一化（normalize_query 全半角/空白压缩）；② L2 多轮上下文补全与注入（A1 历史压缩+最近 6 轮）；③ 安全-频率限制（api/query.py 43002）；④ 韧性-超时控制（request/search/llm 分层超时）。
  - **部分具备 7 项**：口语→书面改写（RuleRewriter 部分）、字符/空白过滤、指代消解（仅生成期句内，非检索前）、反问机制（LLM 生成式澄清存在，非模板）、敏感词（keyword_moderator 组件存在）、越权/域路由（KbRouter，非输入侧租户鉴权）、降级兜底（timeout 兜底，无正式 ResilienceManager）。

  - 当前阶段务实路线更优（避免过度工程，且该文档自承语义缓存命中率仅 3% 等低ROI项）；
  - 但应把文档当"北极星"逐步演进，优先补对本产品真正缺的：意图路由、多意图切分、query结构化提取、熔断、基础可观测。**勿盲抄低ROI项（语义缓存等）**。
