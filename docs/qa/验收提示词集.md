# 验收提示词集：从宣传口径到真实点击

> 目的：把 `README.md` / `README.zh-CN.md` / `PRODUCT_MANUAL.md` / `docs/RAG系统介绍.html`
> 里的对外承诺，翻译成**可点击、可留证、可判定**的验收任务；再用一个专门的缺陷找寻 Agent
> 做对抗性探查。
>
> 适用基线：2026-10-26 工作区（`DEVELOPMENT.md` 第 17 章、`docs/specs/真Agentic_RAG设计.md`）。
> 关联文档：`AGENTS.md`、`docs/specs/测试与评测体系设计.md`、`tests/eval_suite/README.md`。
>
> **最重要的一条**：Agentic 的结论必须以**真实浏览器点击**为准。单测、进程内评测、curl 只能
> 作为补充证据，不能单独把“Agent 模式可用/规划器生效/引用可追溯”判为通过。

## 0. 使用说明（给验收负责人）

### 0.1 这套提示词怎么用

1. **先跑 P0**：把服务、浏览器驱动、隔离工作区副本和证据目录准备好；`P0=BLOCKED` 时后面的
   功能验收全部记 `BLOCKED`，不要用单测替代。
2. **再跑 P1**：静态核对宣传口径，拿到 `claims.json`。P1 的产出决定后续每条断言引用哪句宣传。
3. **功能验收 P2~P11**：按端口/数据隔离矩阵执行（见 §0.4）。UI 类提示词必须留下截图与网络响应。
4. **最后跑 P12**：把前面所有“通过/不通过”先放一边，换一个对抗视角重新找缺陷；再跑 P13 复核，
   剔除误报、合并重复项。
5. 每份提示词都可以**单独粘给一个 Agent**。同一实例上不要并行跑会改数据的提示词（上传/删除/
   建库/重启），否则证据会互相污染。

### 0.2 五条硬规则（建议原样放进每个 Agent 的任务开头）

1. **只认实际交互**：必须用真实浏览器（Chrome + Playwright）执行 `click` / `fill` / `setInputFiles`，
   等待真实 UI 变化；禁止用 `fetch()` 直接调 API 来代替点击，禁止用 `page.evaluate(el.click())`
   伪造点击，禁止 P 图或手写“预期截图”。
2. **不改产品**：不改 `app/`、`frontend/src/`、`configs/settings.yaml`；不 commit、不 push。
   需要开关时只通过 `RAG_*` 环境变量在**新启动的进程**上覆盖，并在报告里写明命令。
3. **不碰密钥**：不读取、不打印 `.env` / 环境变量里的 API Key；只看 `/api/health` 的
   `llm` 状态。截图与日志里不得出现 Key。
4. **证据可复核**：每条结论至少带 1 张截图 + 1 份网络响应（或 DOM 文本/服务端日志），文件落到
   `reports/qa/<run-id>/`，命名见 §0.5。没有证据的结论按“未执行”处理。
5. **可清理**：测试库名统一带 `QA-` 前缀；结束时删除测试知识库/文档/用户，停掉自己起的服务，
   不留下 `data/` 污染。桌面端/团队模式等重流程用独立副本。

### 0.3 判定口径

| 判定 | 含义 | 允许的措辞 |
|---|---|---|
| **PASS** | 宣传承诺的可观察行为在实际点击中成立，证据完整 | “已验证：……” |
| **PARTIAL** | 主路径成立，但宣传里的限定条件、可见性或边界行为不一致 | “成立，但……不成立/未体现” |
| **FAIL** | 承诺的行为与实际不符，或用户按文档操作会失败/被误导 | “实际是……，与……不符” |
| **BLOCKED** | 缺 Key / 模型 / 浏览器 / 依赖，或环境不允许 | “未执行，原因是……” |

`PARTIAL` 不是和稀泥：必须写清“哪一条成立、哪一条不成立”。例如“Agent 能规划（PASS），
但 UI 不显示当前模式，回退时用户无感知（PARTIAL/缺陷）”。

### 0.4 环境与端口隔离矩阵

**重要（2026-10-26 实测）**：`app/core/registry.py:201-204` 的 `wire()` 目前用默认路径构造
`DocumentsStore()` / `KbStore()` / `JobStore()` / `UserStore()`，**没有读取**
`documents.persist_file` / `kbs.persist_file` 配置。因此只设 `RAG_DOCUMENTS_PERSIST_FILE` /
`RAG_KBS_PERSIST_FILE` **不能隔离 KB/文档/任务/用户元数据**，测试库会写进真实 `data/`。

可靠做法：为每个验收实例复制一份工作区（排除 `.git`、`.venv`、`data`、`frontend/node_modules`），
在副本里用**原仓库的 `.venv/bin/python`** 启动；`rsync` 会带上 `frontend/dist`。这样 KB、文档、
Chroma、任务都落在副本的 `data/`，验收结束直接删副本。下面的矩阵按这个方式写。

| 用途 | 端口 | 数据目录 | 关键开关 |
|---|---|---|---|
| 主链路 / Agentic 点击 | 8010 | 副本 `data/`（`/tmp/ragqa/main-*`） | `RAG_ORCHESTRATION_AGENT_ENABLED=true` |
| 格式与入库边界 | 8011 | 副本 `data/`（`/tmp/ragqa/formats-*`） | 默认（Agent 可不开） |
| 团队模式 / RBAC | 8012 | 副本 `data/`（`/tmp/ragqa/team-*`） | `RAG_API_AUTH_ENABLED=true` |
| 桌面端 | 8000 或外部地址 | 桌面默认 `data/` | 独立运行，避免与 8010 冲突 |

启动前导出（副本内）：

```bash
export RAG_API_AUTH_ENABLED=false
export RAG_ORCHESTRATION_AGENT_ENABLED=true
export HF_HUB_OFFLINE=1     # 模型已缓存时；首次下载则去掉
```

> 说明：`RAG_*` 覆盖只影响新进程；`.env` 仍会被读取，但显式环境变量优先。团队模式提示词会单独
> 打开 `RAG_API_AUTH_ENABLED=true` 并设置管理员。若坚持在真实工作区测试，只能用 `QA-` 前缀库并
> 严格清理，且不要删除既有库；这属于降级方案，不作为默认。

### 0.5 证据目录与报告格式

```text
reports/qa/<run-id>/
├── report.md
├── report.json
├── shots/          # 01-open.png, 02-agent-plan.png ...
├── net/            # query-01.request.json, query-01.response.json ...
```

## 2. P0 —— 验收环境自检（先跑这个）

```text
你是验收环境官。目标：把当前工作区启动成一个可点击、可留证、可清理的隔离实例，并判断是否具备继续验收的条件。不要评价功能好坏。

硬约束：
- 只读产品代码；不改 configs/settings.yaml、不改 frontend/src、不 commit。
- 不读取、不打印 .env 或环境变量中的任何密钥；只看 /api/health 的 llm 状态。
- 所有命令在仓库根目录执行；服务必须用 frontend/dist 构建产物（不是 vite dev）。
- 若 llm != ok，立即输出 BLOCKED；禁止用 Stub/单测/curl 替代真实点击验收。

步骤：
1. 记录基线：ORIG=$(pwd)、git rev-parse HEAD、git status --porcelain、
   shasum frontend/dist/index.html、node -v、.venv/bin/python -V。
2. 建证据目录 RUN=/tmp/ragqa/$(date +%Y%m%d-%H%M%S)；复制一份工作区（避免污染真实 data/）：
   REPO=/tmp/ragqa/repo-$(date +%Y%m%d-%H%M%S)
   rsync -a --exclude .git --exclude .venv --exclude data --exclude reports \
     --exclude frontend/node_modules --exclude .coverage --exclude .pytest_cache \
     "$ORIG/" "$REPO/"
   cd "$REPO"
   （说明：wire() 目前不读取 documents/kbs 的 persist_file 配置，单靠 RAG_* 无法隔离 KB 元数据，
    必须用副本；副本会带上 frontend/dist。不要复制 .venv，用原仓库的 $ORIG/.venv/bin/python。）
3. 导出：RAG_API_AUTH_ENABLED=false、RAG_ORCHESTRATION_AGENT_ENABLED=true、
   HF_HUB_OFFLINE=1（模型已缓存时；首次下载则去掉）。选一个空闲端口（8010 起，最多试到 8019），
   后台启动：
   "$ORIG/.venv/bin/python" -m uvicorn app.main:app --host 127.0.0.1 --port <PORT>
   日志写 $RUN/server.log，PID 写 $RUN/server.pid。
4. 轮询 http://127.0.0.1:<PORT>/api/health，最多 300 秒；要求 embedding=ok、vector_store=ok、
   llm=ok。llm=not_loaded 时输出 BLOCKED，并附 server.log 最后 40 行（先脱敏）。
   初次常先返回 degraded/embedding=not_loaded，继续轮询，不要过早判失败。
5. 在 $RUN/e2e 安装浏览器驱动（不写入仓库）：
   npm init -y; npm_config_cache=$RUN/npm-cache npm i playwright-core
   （npm 默认缓存可能无写权限，必须指定临时 cache；已实测 playwright-core + channel:'chrome' 可启动。）
   用 Chrome 通道启动，打开 http://127.0.0.1:<PORT>/，等 #app 渲染；
   断言页面标题、左侧四个导航（问答控制台/文档管理/知识库管理/设置总览）、右上角“反思/自动/Agent”分段控件；
   截图 $RUN/shots/00-boot.png；打印 document.title 与 #app 的 innerText 前 500 字。
   若 channel:'chrome' 失败，改用 executablePath=/Applications/Google Chrome.app/Contents/MacOS/Google Chrome。
6. 输出 $RUN/env.json 与一段 READY/BLOCKED 结论：
   {commit, dist_sha, port, health, llm, browser, run_dir, repo_dir, verdict, blockers[]}
   附上启动命令、PID、日志路径、副本路径（验收结束后删除副本）。

不要做：不要跑 pytest 代替启动检查；不要创建知识库；不要改真实工作区的 data/；不要删除副本之外的任何目录。
```

**通过标准**：`verdict=READY`；`llm=ok`；浏览器能打开 SPA 并看到四个导航与三个模式选项。

## 15. P13 —— 缺陷复核与裁决 Agent（防止误报/刷量）

```text
你是缺陷复核 Agent（meta-QA）。输入是 P2~P12 的 defects.json 与证据目录；你的任务是证实/证伪/合并，
不是再找新缺陷（发现新问题可另开“新发现”区）。

步骤：
1. 逐条读缺陷：承诺出处、预期、实际、复现步骤、证据文件。缺证据的直接标 NEED-EVIDENCE，不进入最终清单。
2. 在干净环境（新副本/新端口）按复现步骤重跑：
   - 能稳定复现 → 保留；
   - 不能复现 → 标 FLAKY，记录尝试次数与环境差异；
   - 复现结果与描述不符 → 标 INVALID，写清差异。
3. 对照 README 的 Known limitations 与 DEVELOPMENT 17.x：
   - 规格明确允许的行为 → 降级为“已知限制/非缺陷”；
   - 规格要求但实现缺失 → 保留；
   - 文档之间冲突 → 单列 DOC-CONFLICT，不硬判产品缺陷。
4. 合并同根因条目；按 S1~S4 重排；把“UI 文案”与“功能失效”分开。
5. 输出 final-defects.md/json：
   - accepted[]：复核通过，含证据与修复方向；
   - rejected[]：误报/已知限制/不可复现，含理由；
   - doc_conflicts[]：文档口径冲突；
   - coverage_gaps[]：本轮没覆盖到的承诺。
6. 给出一页结论：能否宣称“达到宣传”？按承诺逐条 TRUE/PARTIAL/FALSE/BLOCKED，
   不允许用“整体基本可用”糊弄。

禁止：不要为了让报告好看而保留无法复现的条目；不要把 S3 写成 S1；不要修改产品代码。
```

## 17. 附录 B：浏览器最小骨架（供各提示词复用）

> 说明：放在 `/tmp` 下，不写入仓库；`playwright-core` 复用系统 Chrome，不下载 Chromium。

```bash
RUN=/tmp/ragqa/$(date +%Y%m%d-%H%M%S)
mkdir -p "$RUN/e2e" "$RUN/shots" "$RUN/net"
cd "$RUN/e2e" && npm init -y >/dev/null 2>&1 && npm_config_cache="$RUN/npm-cache" npm i playwright-core
```

```js
const { chromium } = require('playwright-core');
const fs = require('fs');

(async () => {
  const base = process.env.BASE_URL || 'http://127.0.0.1:8010';
  const out = process.env.RUN_DIR || '/tmp/ragqa/run';
  const browser = await chromium.launch({ channel: 'chrome', headless: true });
  const page = await browser.newPage({ viewport: { width: 1440, height: 900 } });
  page.on('console', (m) => console.log('[console]', m.type(), m.text()));
  page.on('response', async (r) => {
    if (!r.url().includes('/api/query')) return;
    try {
      const req = r.request();
      const body = req.postData() ? JSON.parse(req.postData()) : {};
      const json = await r.json();
      const tag = body.mode || 'unknown';
      fs.writeFileSync(`${out}/net/query-${tag}-${Date.now()}.request.json`, JSON.stringify(body, null, 2));
      fs.writeFileSync(`${out}/net/query-${tag}-${Date.now()}.response.json`, JSON.stringify(json, null, 2));
    } catch (e) { console.log('[net] capture failed', e.message); }
  });

  await page.goto(base + '/', { waitUntil: 'networkidle' });
  await page.screenshot({ path: `${out}/shots/00-boot.png`, fullPage: true });
  console.log(await page.title());
  console.log((await page.locator('#app').innerText()).slice(0, 500));
  await browser.close();
})();
```
