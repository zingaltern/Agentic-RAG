# 开发指令 03：13.10 P3 可选适配器包（OCR/表格/多分块/多 embedding/多 LLM）

> 依据：DEVELOPMENT.md 13.10（只立规格、未排期）+ 15.2（格式边界）。
> 状态：未开工（规格已立；触发条件：用户决策 + 13.1 度量协议验证）。
> 原则：全部为**可选适配器**——接口契约与核心编排不动，仅新增/扩展 `app/adapters/`，默认关。

## 任务 3.1：OCR（扫描件 PDF / 图片）

- 现状：`app/adapters/parser/ocr.py` `_parse_ocr` 预留接口，当前抛错"OCR 未启用"；`PARSERS` 注册表（`parser/registry.py`）已就绪。
- 做法：
  1. 选引擎并登记依赖（`pyproject.toml`）：推荐 `paddleocr`（中文效果好）或 `pytesseract`（轻量，需系统 tesseract + 中文语言包）。两者选一，写明理由。
  2. `_parse_ocr` 实现懒加载引擎；配置 `parser.ocr.enabled=false` 默认关、`parser.ocr.engine`、`parser.ocr.lang`。
  3. `configs/settings.yaml` 新增 `parser:` 段（`ocr: {enabled: false, engine, lang}`）；`core/config.py` 加 `ParserConfig`。
  4. 扩展 `PARSERS` + `SUPPORTED_EXTENSIONS` + `allowed_extensions`：图片 `.png/.jpg/.jpeg/.bmp/.tiff`；魔数校验补图片头（PNG `\x89PNG`、JPEG `\xff\xd8\xff` 等）——`_check_magic` 扩展。
  5. 前端 `DocumentsView.vue` `SUPPORTED_ACCEPT/TYPES` 同步（可放下一轮，因 OCR 默认关）。
- 验收：10 份含图 PDF/图片抽文且检索命中 ≥ 阈值（`make eval` 对比）；未开启时上传图片返回明确错误（40001 或现有语义）。

## 任务 3.2：表格结构保留（xlsx/表格区深化）

- 现状：PDF 表格已转 Markdown（P-B 交付）；xlsx 每行 `\t` 连接为段文本（`_parse_xlsx`）。
- 做法：
  1. `_parse_xlsx` 输出结构化标记：表头行与数据行区分，格式 `|列名|值|`；metadata 增加 `table_cells`（列名列表）与 `kind=="tab"`。
  2. chunker 对 `kind==tab` 的块保留整表不切碎（`app/adapters/chunker/__init__.py` 按 metadata 分派，纯函数扩展签名时保持默认参数向后兼容）。
  3. 检索侧：`hybrid_rrf._metadata_filters` 已支持 metadata 等值过滤，确认 `table_cells` 可作为过滤键（无需改契约）。
- 验收：表格问答 qa_pairs 子集通过率达标；`make eval` 对比报告。

## 任务 3.3：多分块策略 + 混合分派

- 现状：`chunker.provider` 仅 parent-child 一种；`split_chunks` 纯函数单实现。
- 做法：
  1. `core/config.py` `chunker.provider` 允许 `"mixed"`：按文档 `kind` 分派（表格→按表成块；文本→现有 parent-child）。
  2. **每加策略必须先用 qa_pairs 标定再上配置**（13.10 硬要求）——先产出 `make eval` 基线对比再合并。
- 验收：各 kind 命中率 ≥ 基准 + `make eval` 对比报告。

## 任务 3.4：embedding 多模型

- 现状：`local_bge_v15`（BAAI/bge-small-zh-v1.5，512 维）；`configs/settings.yaml` `embedding:` 段。
- 做法：
  1. 允许配置切换 `bge-small/base/large-zh`/`bge-m3`（`embedding.model_name` 已支持）。
  2. 换模型=维度变化 → 需全量重入库：实现 `make reindex`（CLI：清空向量库对应集合 + 重新 ingest 全部文档），或文档明确"手动重建"步骤。
  3. metadata 加 `embed_model` 版本标记（写入 Chunk.metadata，检索侧可校验维度一致）。
- 验收：两档切换指标（Hit@1/Faithfulness）对比有记录（`make eval` × 2）。

## 任务 3.5：LLM 多协议

- 现状：仅 `deepseek`（OpenAI 兼容 HTTP）。
- 做法：
  1. `app/adapters/llm/` 新增 `OllamaLocalLLM`、`OpenAICompatibleLLM`（实现 `LLM.chat` 接口，§3.8）；`llm.provider` 允许切换（`core/config.py` ALLOWED_PROVIDERS 已含 ollama/openai_compat，检查接线）。
  2. 前端「设置总览」加模型选择下拉（`SettingsView.vue`），保存后写配置/重启生效。
  3. 可选：DeepSeek 失败可 One-pass→Ollama 兜底（`orchestration` 捕获 `LLMUnavailableError` 后切 provider 重试一次）。
- 验收：三 provider 各跑通 1 条问答（curl /api/query 冒烟）。

## 公共要求

1. 每个适配器有单测（Stub 隔离，确定性）；全量 `make test` 全绿（基线 327 项），更新 AGENTS.md 计数。

3. 不改变 `core/interfaces.py` 现有契约签名（如需扩展，加默认参数保持向后兼容，并更新 test_contracts）。
4. 依赖新增登记 `pyproject.toml` 并注明理由。
