# 开发指令 05：移除 A4 多库自动路由（kb_router）

> 依据：2026-08-30 用户架构评审决策（多库基础设施**保留**；自动路由层**移除**）。
> 性质：规格变更 —— 按流程先修订本设计文档与 `DEVELOPMENT.md`（14.4/15.5），再动代码。

## 1. 背景与决策（需求设计 + 需求评审）

- 现状：A4 多库自动路由（2026-08-16 交付）在用户未指定 `kb_id`（或显式传 `"auto"`）时，
  按「查询词 × 库名/描述/文档标题」词面覆盖 + 可选向量相似度打分自动选库。
  `kb_router.enabled` 默认 `false`；**前端从不依赖**（始终显式传 kb_id 或缺省 default）。
- 决策（用户 2026-08-30 指令批准，需求评审通过）：
  1. **多库基础设施保留**：`kb_id → collection（rag_<id>）` 物理隔离与库级权限
     （shared/private + owner）是企业 RBAC 与部门库的载体，成本已沉没且干净；
  2. **自动路由层移除**：前端已有显式选库交互（一秒成本）；企业场景路由误选
     （A 库问题拿 B 库文档作答）的代价高于手选；且该休眠路径存在已知缺陷（见 2.3）。

## 2. 方案设计（方案评审：随本文档留档，2026-08-30）

### 2.1 改动清单

### 2.2 行为变更（契约收紧）

- kb 解析链由四段化三段：**kb_id 显式指定 → collection 反查 → 缺省 default**
  （删除中间的 auto 段；`kb_router.enabled` 开关随之消失）。
- `kb_id="auto"` 不再是魔法值：按普通 kb_id 处理，库不存在 → `40001`（原先会被路由吞掉）。
- 默认行为零变化：现状部署 `kb_router.enabled=false`，请求本来就走 `default` 兜底；
  前端无感（grep 确认 frontend/src 无任何 auto/kb_router 依赖）。

### 2.3 随移除消除的已知缺陷

- `_route_kb` 无匹配返回 `None` 时，`collection` 兜底 default 但 `info=None` 透传给
  `can_read_kb(user, None)`（`app/api/query.py:113-123` + `app/services/rbac.py:22-27`）：
  普通用户触发 `AttributeError → 50001`，而非按 default 库正常作答或 40101。
  该缺陷仅存在于休眠路径（`kb_router.enabled=true` 且打零分时），随路由分支一并消失。

### 2.4 风险与回滚

- 风险：极低 —— 被删链路默认关闭、前端无依赖、删除面有显式单测清单；
  `KbStore`/collection 命名/数据均不动，无迁移。
- 回滚：git revert 单提交即可。
