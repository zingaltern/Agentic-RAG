## 2. 方案设计（每项：问题 → 设计 → 锚点 → 测试 → DoD）

### P0-1 解析质量门禁（空文本/乱码拒绝）

- **问题**：扫描版 PDF 抽出空文本会"成功"入库 0 块；乱码（U+FFFD）静默混入正文，用户与系统均无感知。
- **设计**：
  1. parser 探针：`_parse_pdf` 逐页统计 → `metadata["text_stats"] = {total_chars, page_count, pages_with_text}`；`garbled_ratio`（U+FFFD 字符数 / total_chars）在 `_build_document` 统一计算（覆盖全部解析器，txt/html/eml 的 `errors="replace"` 也产生 U+FFFD）。
  2. 质量检查提取为 parser 模块级可复用函数 `evaluate_parse_quality(text, text_stats, *, min_text_chars, max_garbled_ratio, min_pages_with_text_ratio) -> list[str]`（返回 flag 列表，空=通过；`min_pages_with_text_ratio` 仅对多页 PDF 生效）。
  3. 门禁（ingestion `_run()`，parse 之后、desensitize 之前）：`ingestion.quality_gate = {enabled: false, mode: reject|flag, min_text_chars: 30, max_garbled_ratio: 0.05, min_pages_with_text_ratio: 0.2}`；reject → 抛 `QualityGateError`；flag → `doc.metadata["quality_flags"]` 打标 + warning 继续；关闭时维持现状。mode 非法值启动即抛 SystemConfigError（config validator）。
  4. `QualityGateError` code=**30005**（30004 已被 RerankError 占用），message「文档解析质量不达标（疑似扫描件/损坏文件）」；ingestion 错误映射表加该分支；DEVELOPMENT 2.2 错误码表同步。
- **锚点**：parser/__init__.py:85-106（parse_file）、:171-207（_parse_pdf 逐页 :184）、:24-43（_build_document）；ingestion.py:157（parse）与 :161-164（desensitize）之间插门禁；:262-278 错误映射加分支；errors.py AppError 模式（:9-18）。
- **测试**（tests/unit/test_quality_gate.py，夹具模式参考 test_parser.py 用 fitz 真实构造、test_ingestion.py 的 deps fixture）：空文本 PDF、乱码率超限、flag 放行且打标、reject → Job failed=30005、enabled=false 行为不变、mode 非法值 load_config 抛 SystemConfigError。
- **DoD**：扫描件 reject 模式 Job failed 30005；正常文档零影响；make test 全绿。

### P1-4 表格一等公民：不跨块切割 + 双轨存储〔eval〕

- **问题**：表格被降维为 `[TABLE]` Markdown 混入正文，token 聚合拦腰切断；无结构化 JSON，"对比两季度营收"类查询只能靠向量猜。
- **设计**（轻量标记路线）：
  1. parser：`Document.metadata["tables"] = [{index, header, rows, page}]` 顺序对应 text 中第 N 个 `[TABLE]` 块。**PDF** 复用 find_tables 结果（parser:229-253）；**docx 补保序标记化**（当前表格无标记且追加在段落末尾——改为按 body 顺序遍历 paragraphs+tables，表格位置输出 [TABLE] 块并登记 tables）；xlsx 整文档即表，v1 不动（followup）。
  2. **reindex_tables(doc)**：cleaner 会改写 text 导致 [TABLE] 与 tables 序号错位 → 清洗完成后按 [TABLE] 出现顺序重扫对齐；清洗删掉表格则丢弃对应 JSON + warning。cleaner 改动：normalize 白名单跳过 [TABLE] 块内内容；**dedup/quality 豁免含 [TABLE] 的段落**（双 `\n` 分段粒度错位风险，评审修正 #2）。
  3. chunker（split_chunks）：items 构建处（:122-123）预扫描 [TABLE]...[/TABLE] 为原子单元，不参与句子聚合——整表 ≤ parent_target_tokens → 单独父块（`metadata["chunk_type"]="table"`、`metadata["table_json"]=json.dumps(...)`，不产子块）；超限 → 语义行组切（每组 ≤ `max_rows_per_chunk`（默认 30）行且强制携带完整表头，`metadata["table_part"]="2/3"`）；JSON 超 `json_max_bytes`（默认 4096）截断 + warning。
  4. **明确范围**：Chroma 标量 metadata 做不了 JSON 内字段级过滤——"metadata filter 精确查询"不在本期（followup）；v1 收益 = 表格完整性 + JSON 随 chunk 供生成阶段使用。
  5. 配置 `chunker.table_aware = {enabled: false, max_rows_per_chunk: 30, json_max_bytes: 4096}`；关闭时 [TABLE] 走普通聚合，行为不变。
- **锚点**：parser/__init__.py:229-253（PDF 表格）、:256-289（_parse_docx）；chunker/__init__.py:97-176（split_chunks）、:122-123（items 构建）、:128-145（聚合）、:148-163（emit）；cleaner/__init__.py:96-108（clean）、:112-138（normalize/noise）、:144-166（dedup）、:65-77（quality）；ingestion.py:167-179（cleaner 块，reindex 调用点在 :179 后）。
- **测试**（tests/unit/test_chunker_table.py）：小表单块不切断、大表行组带表头、正文与多表混排、reindex 对齐/错位丢弃、JSON 截断、docx 表格保序、enabled=false 回归。
- **DoD**：make eval 前后对比（重点表格类问题 recall；off 回归无差异 + on 对比两份）；抽查表格块 metadata.chunk_type=table 且含完整表头；make test 全绿。

### P1-5 标题硬边界 + 上下文前缀 + 页码溯源〔eval〕

- **问题**：父块聚合纯按 token 数，章节被拦腰切开；chunk.text 缺上下文（"该公司…"孤立段落检索不到）；PDF 多页 page=None（parser:196 注释自认"留待 W2"）。
- **设计**：
  1. 页码映射（parser）：`_parse_pdf` 拼接各页时记录行号区间 → `metadata["page_spans"] = [[start_line, end_line, page], ...]`；pptx 以 slide 号为页码；docx 维持 None。
  2. chunker：**硬边界**——聚合父块时 section 归属变更（:110-114 已有归属、:128-145 聚合循环 :130 token 判断处）强制 flush，标题行作为新块首行；**页码**——按段落起始行号查 page_spans → `metadata["page"]`（None 不写）；**上下文前缀**——`chunk.text = f"{doc_title} > {section}\n" + 原文`（emit :148-163，模板可配；前缀不计入切块 token 目标（按原文计），计入 embedding 输入——前缀 >64 token 截断 + warning；父子块一致加前缀）。
  3. 配置独立开关：`chunker.hard_boundary = {enabled: false}`、`chunker.context_prefix = {enabled: false, template: "{doc_title} > {section}", include_page: false}`。
  4. eval 按 13.1 分两次：先开 hard_boundary 出一份对比，再叠加 prefix 出第二份（分开归因）；负收益则回调模板或回退开关。
- **锚点**：parser:184-199（page 循环与 page=None 注释）、:314-329（pptx）；chunker:80-90（_build_line_sections）、:110-145（归属与聚合）、:148-163（emit）。
- **测试**（tests/unit/test_chunker_boundary.py）：标题强制断块、跨 section 不粘连、多页 PDF page 映射、前缀模板渲染/无 section 降级/超长截断、enabled=false 回归。
- **DoD**：两份 make eval 对比报告；抽查多页 PDF 的 chunk.metadata.page 非空；make test 全绿。

### P2-7 阶段级指标 + Job 阶段计时

- **设计**：

  2. 新模块 `app/core/metrics.py`：**零新依赖**（不引 prometheus-client，1.1 依赖锁定）；线程安全 Counter/Gauge/Histogram（固定桶 .05,.1,.25,.5,1,2.5,5,10,30）。
  3. 指标集：`rag_ingest_stage_seconds{stage}`（histogram）、`rag_ingest_total{result=success|failed|duplicate|rejected}`（按 error_code 分 label）、`rag_ingest_queue_depth`（gauge）、`rag_query_total{result}`。
