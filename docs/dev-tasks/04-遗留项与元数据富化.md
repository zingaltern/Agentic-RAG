# 开发指令 04：14.4 遗留项 + 元数据富化（T5）

> 依据：DEVELOPMENT.md 14.4（已知遗留）+ 分析师文档《数据清洗与格式_开发要点.md》T5。
> 性质：均为"不做不阻塞、触发再做"的遗留项；每项可独立排期、独立验收。

## 任务 4.1：T5 元数据抽取与富化（分析师 P1，推荐优先）

- 现状：解析时 metadata 仅 `source/kind/content_hash/page/author`（+xlsx sheets）；Chunk 无 `section`（章节标题）；检索 filters 已支持 metadata 等值过滤（`hybrid_rrf._metadata_filters`）。
- 做法：
  1. 解析器富化：`_parse_text/_parse_pdf/_parse_docx` 等提取章节标题（Markdown `#` 行 / PDF 字体大小差异 / docx heading 样式）→ 后续块继承 `section`。
  2. `split_chunks` 返回的 Chunk 携带 `section`（当前 chunk 所属最近章节标题）写入 `chunk.metadata["section"]`。
  3. `_build_document` 增加 `title/author/date`（PDF/docx 元数据已有 author，补 date）。
  4. 检索侧无需改动（filters 机制已支持 `{"metadata": {"section": ...}}`），但需在 `/api/query` 的 filters 透传路径确认支持（`app/api/query.py`）。
- 验收：入库后 Chroma 元数据含 section/title/date；按 `filters={"metadata":{"section":"年假制度"}}` 检索命中；单测覆盖。

## 任务 4.2：RBAC 深度扩展（文档级/多角色矩阵）

- 现状：kb 级（owner/scope=shared|private，`app/services/rbac.py` Authorizer）；普通用户建库强制私有。
- 做法（12.3 深度 C，需先立规格）：文档级权限（owner/reader/writer 列表）、角色矩阵（admin/manager/user）、`Authorizer` 扩展接口 + `rbac.py` 实现 + 权限测试（`tests/unit/test_auth.py` 扩展）。
- 验收：文档级读写/可见性单测矩阵；现有 kb 级行为不回归。

## 任务 4.3：契约同步自动化（openapi → TS）

- 现状：手写前端类型（`frontend/src/` 无 generated types）。
- 做法：后端导出 OpenAPI（FastAPI 自带 `/openapi.json`）→ openapi-typescript 生成 `frontend/src/api/types.ts`；脚本化；前端 api 调用改用生成类型。
- 验收：`npm run typecheck`（如配置）通过；生成文件入仓库。

## 任务 4.4：事件钩子（文档变更→缓存失效）

- 现状：仅 KbStore 钩子；Chroma 有 `mutation_epoch`（`chroma_store.py:34`）供 BM25/父块缓存失效，但无通用事件总线。
- 做法：轻量事件总线（`app/core/events.py`，pub/sub in-process）——`document.ingested/deleted/kb.deleted` 事件 → 订阅者失效缓存/重建索引；或确认现有 epoch 机制已覆盖（若已覆盖则文档化即可，无需新代码）。
- 验收：上传/删除后缓存失效被触发（单测断言 hook 调用）。

## 任务 4.5：CI 基线门禁

- 现状：无 CI；`make test` 人工跑。
- 做法：GitHub Actions（或现有托管 CI）——PR 跑 `make test`（覆盖率门禁 >=80%）+ `npm run build`；可选 `make eval` 基线对比（失败留痕不阻断）。
- 验收：推送测试分支触发流水线全绿。

## 任务 4.6：会话持久化 / 流式输出

- 现状：`stores/app.js` `chat.messages` 内存态，刷新丢失；`/api/query` 一次性返回（无 SSE）。
- 做法（产品明确要求时单独立项，D 组评估结论）：
  1. 会话持久化：后端 `POST /api/sessions`（存储 + 列表），前端登录后按会话加载历史。
  2. 流式输出：`/api/query/stream` SSE（chunk 级 token 流），前端打字机效果。
- 验收：刷新后历史可恢复；流式问答端到端可用；`make test` 全绿。

## 任务 4.7：发布打包（Python 运行时捆绑）

- 现状：`frontend` 可用 `electron-builder --mac dmg` 打包前端壳；后端依赖 `.venv`（Python 3.11 + torch 等），未捆绑。
- 做法（正式发布前决策）：
  1. 评估方案：PyInstaller 捆绑后端 vs 要求部署机预装 Python+venv（现状）vs Docker。
  2. 若捆绑：`electron-builder` extraResources 携带后端产物 + 启动脚本改 bootstrap（`frontend/electron/bootstrap.cjs` spawnBackend）。
- 验收：打包后双击 .app 可完整启动（含后端）→ 登录 → 上传 → 问答。

## 公共要求

1. 每项独立单测；全量 `make test` 全绿（基线 327 项），更新 AGENTS.md 计数。
2. 不改变现有接口契约（`core/interfaces.py` 签名）+ 不破坏 kb_id 隔离与鉴权。
3. 完成后在 DEVELOPMENT.md 14.4 表格更新对应行状态（已交付+日期）。
