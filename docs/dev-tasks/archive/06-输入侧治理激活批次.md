# 开发指令 06：输入侧治理激活批次 V1（T1 绝望短路 / T2 极简通道扩容 / T3 服务端会话接通）

> 依据：《docs/specs/在线侧输入处理.md》可落地性评估（2026-08-30）——四档结论中的"已验证可落地 + 可低成本补齐"两档。
> 对应方案愿景：V1.0（L0 分级收尾 + L1 标准化 + 基础路由）中在本系统形态下性价比最高的子集。
> 性质：小步规格变更 —— 先修订本设计文档与 `DEVELOPMENT.md`（13.13 新增 + 4.2 schema + 14.4），再动代码。

## 1. 背景与决策（需求设计 + 需求评审）

- 现状（评估结论，2026-08-30）：
  1. **域外/闲聊查询空转**：首轮评估分已暴露无望信号，但循环仍跑满 3 轮（每轮检索 + 可能调 LLM 改写）；
     基线中 D059/D061（no_answer 类）因 3 轮后以 21003 澄清收尾而违反 no_answer 判据被判 FAIL；
  2. **L0 极简通道近乎空置**：`greeting.enabled=false` 默认关，仅 3 条问候正则共用一条回复，
     闲聊/身份认知/能力边界类问题全部落入重链路；
  3. **L2 服务端会话建成未用**：13.12.6 全量交付（session_store/rule_boundary/回写），但
     前端从不发送 `session_id` 且 `dialogue.enabled=false`——整条链路无人激活。
- 决策（用户 2026-08-30 指令"把可落地的做出来"，需求评审通过）：本批次实现 T1/T2/T3 三项，
  其余（合并意图 LLM 调用、L4 结构化提取、tool_call、Redis/多实例/可观测栈）按评估结论
  留档为后续批次或部署升级项（见 §5）。

## 2. 方案设计（方案评审：随本文档留档，2026-08-30）

### T1 绝望短路（编排循环内，约 15 行）

- 新增配置：`orchestration.hopeless_shortcut: bool = True`、
  `orchestration.hopeless_score_threshold: float = 0.15`。
- 行为：`iteration == 0` 且评估未通过且 `score <= threshold` 且 `web_active=False` 且
  `history` 为空 → 跳过改写轮，直接返回 21001 兜底文案（FALLBACK_TEXT）。
- **不触发 21003 澄清**：域外查询的诚实答案是"未找到相关依据"，而非"您想了解哪方面"；
  这同时使 no_answer 类评测项回归 `code=21001` 判据（修复基线 D059/D061）。
- **历史豁免（T3 冒烟发现，2026-08-30）**：带会话历史的低分查询可能是针对历史的追问
  （"我上一条消息说了什么"与 KB 语义无关但可由历史作答），短路会截断追问 → history 非空不短路。
- 默认开启的例外说明：13.12 的"默认关"原则针对**改变外部行为的新治理层**；T1 只缩短
  "分数远低于通过线（0.45）且本就必然以 21001 收尾"的查询的空转路径，外部语义不变、
  仅更快，且以 `make eval` 全量回归为门禁（若任何用例回退则调阈值或改默认关）。

### T2 L0 极简通道扩容 + 默认部署启用

- `GreetingConfig` 新增 `rules: list[GreetingRule]`（`{name?, pattern, reply}`，每条规则独立回复）；
  匹配顺序：`rules` → 旧版 `patterns + reply`（兼容字段保留，rules 为空时生效）；
  单个正则非法跳过（沿用 13.12.4 降级语义）；挂接点不变（`run()` 起点，不检索不调 LLM）。
- `configs/settings.yaml`：`greeting.enabled: true` + 7 条规则（问候/在场/致谢/身份认知/
  是否机器人/实时天气/实时日期时间）。**代码默认保持 false**（部署级激活，与
  `auth_enabled` 同范式）；identity/realtime 规则的回复明确声明能力边界。
- 已知取舍：本批次**不做**"greeting 上移 API 层"重构（纯重构无用户价值，挂接点变更
  影响面大），列为后续项。

### T3 服务端会话接通（激活 13.12.6 L2）

- 前端 `stores/app.js`：state 增 `sessionId`（`localStorage.rag_session_id` 持久化，惰性
  生成 `crypto.randomUUID()`）；actions 增 `ensureSessionId()` / `resetSession()`；
  `logout()` 同步重置会话（防串号，与清 chat 同理）。
- 前端 `QueryConsole.vue`：`ask()` 携带 `session_id`（仍发送 `history` 作兼容——
  服务端 dialogue 关闭时为现状语义）；「清空对话」按钮同时 `resetSession()`（新会话 =
  服务端历史/澄清计数重置）。
- 部署配置：`configs/settings.yaml` `dialogue.enabled: true`（代码默认仍 false）。
- 生效语义（13.12.6 不变）：服务端历史优先；新话题边界判定清空短期上下文；
  回溯关键词移除上一轮；澄清按 session 计数（max_rounds=2），正常回答清零。
- 上下文长度影响评估：客户端历史 → 编排取 `history[-6:]`（3 轮）；会话 `max_rounds=5`
  → 同样收敛到 `history[-6:]`（3 轮）——**有效上下文不变**，仅新增边界清空/回溯/澄清计数收益。

## 4. 验收（DoD）

1. `make test` 全绿（覆盖率门禁 ≥80%），新增用例覆盖 T1 四分支与 T2 rules 匹配/降级；
2. `make eval` 进程内全量对比基线（2026-08-30：105/107、Hit@1=87%、Hit@5=100%）：
   **不回退**，且 no_answer 类（D059/D061）预期由 21003 转 21001 改善为 PASS；
3. `cd frontend && npm run build` 成功（dist 随仓库约定提交）；
4. 手工语义抽查：问候/闲聊/实时信息问法短路返回对应回复；带 session_id 连续提问服务端历史生效。

### 4.1 实测结果（2026-08-30）

- `make test`：**429 项全绿**（新增 9 用例），覆盖率 **91.03%**；
- `make eval`（最终代码态）：**107/107 通过**（基线 105/107，D059/D061 转 PASS），
  Hit@1=87%、Hit@5=100% 持平；报告 `reports/eval-20260830-174843.md` 及其后；
- 前端 `npm run build` 成功；
- 真实后端冒烟（临时实例 :8010，真实 DeepSeek）：
  - "你好" / "今天天气怎么样" → 极简通道直达回复，iter=0 ✅
  - "量子力学的波函数坍塌原理" → T1 短路 21001，iter=0，仅首轮检索 ✅
  - 会话追问（内容相关）→ 历史保留、iter=1、未被短路 ✅（T3 管道验证）

### 4.2 冒烟发现的已知边界（如实记录，后续项输入）

1. **规则边界判定器的元问题盲区**：边界判定按 4.3.2 规格 query-vs-query 双维比较，
   "我上一条消息说了什么"类元问题与上一轮查询词面/语义双低 → 误判新话题清空历史 →
   该类追问退化为无历史短路（修复后为无历史正常循环）。属规格内行为，根治需
   L3 合并调用做指代/元问题理解（本设计文档 §5 已留档）。
2. **历史记忆问答的生成契约冲突**：SYSTEM_PROMPT 强约束"只基于知识库上下文回答 + 必须引用 [N]"，
   实测模型拒绝从会话历史复述用户自述事实（"我的工号是多少"答"知识库中未找到"）。
   服务端历史管道本身已验证；允许"无引用的会话性回答"需调整生成契约（影响全部回答与评测），单独立项。
