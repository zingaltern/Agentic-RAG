## 1. 背景与决策

- 差距评估结论：对标平台的查询改写是策略组合（Step-Back 抽象化 / HyDE 假设文档 / 复杂改写），本项目仅有单一 LLM 改写+规则兜底；且缺少从查询解析结构化范围线索（文件名/章节）直接缩小检索面的能力。
- 决策（用户 2026-09-07 选定方向）：本批次做 Q1+Q2；Deep Mode/真规划器留 P-D 立项，SSE/会话持久化留交付形态批次。

## 2. 方案设计

### Q1 多策略改写（HyDE / Step-Back，扩展 llm 改写器为合并调用）

- 配置（RewriterConfig 增两开关，默认关）：`rewriter.step_back_enabled: false`、`rewriter.hyde_enabled: false`。
- 行为（`LLMRewriter.rewrite`）：
  - 两开关均关 → **现行为零差异**（旧 JSON 数组提示词与解析路径）；
  - 任一开启 → **一次合并 LLM 调用**（在线侧方案"合并调用"理念，省多次往返）输出 JSON 对象：
    `{"rewritten": ["改写变体 1~3"], "step_back": "抽象化的一般性问题", "hyde": "100~200 字假设性答案段落"}`；
  - 产出变体序列：rewritten（path=hybrid）+ step_back（path=hybrid）+ hyde（**path=vector**——假设性段落以向量检索才能发挥"文档邻域"效果，BM25 长文本会污染词面排序）；去重、剔除与原 query 相同者；
  - 失败/超时/解析失败 → 既有 rule 回退（单变体），不阻塞；
  - 返回类型演进：`str | list[str] | list[dict{"text","path"}]`（core/interfaces.py QueryRewriter 契约注释同步——编排层按类型适配，既有 str/list 生产者不受影响）。
- 编排适配（`_rewrite_variants`）：normalize dict 变体（text/path，缺省 hybrid）；debug_trace/换路判定逻辑不变。
- 反思循环硬约束不变：每轮 query 必变、filters/collection 贯穿全部变体（hyde 变体同样受 filters 约束）。

### Q2 Scope 路由 lite（确定性文件名线索 → source 过滤）

- 新模块 `app/services/scope_router.py`（纯函数）：`extract_scope(query, filenames) -> dict | None`——
  线索识别：①书名号 `《名称》` ②引号 `"名称"` ③已知文件名/词干在 query 中的精确子串匹配；
  命中**唯一**文件 → `{"metadata": {"source": "<原文件名>"}}`；命中多个（歧义）或零命中 → None（不猜）。
- 配置：顶层 `scope_router = {enabled: false}`。
- 挂点（`app/api/query.py`）：kb 解析与权限校验之后——`enabled` 且用户未显式给 `filters.metadata` 时，
  按**目标库**文档清单提取线索；命中则合并 filters（**用户显式 filters 恒优先**），info 级日志记录应用的 scope。
  提取函数与合并逻辑拆为可直测的纯函数/小函数。
- **明确不做**（followup）：章节/日期线索（需先建 section 值域索引）、歧义消解反问、LLM 参与的 scope 解析。
